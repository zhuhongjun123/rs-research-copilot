# rs-research-copilot

遥感科研辅助**综合智能体**（检索 · 生成 · 审查）—— 直接读你**本地的 Zotero 文献库**：

1. **论文数值自洽审查** —— 抓出同一篇论文内部的数值矛盾
2. **可溯源问答** —— 基于你的文献库回答，每条含数值的断言**回查核验**，证据不足时**拒答**

> 「检索 · 生成 · 审查」中的**生成**目前指**基于检索证据作答**（不是写论文/综述）；**审查**指数值自洽检查。

> **它解决什么问题**：把论文 PDF 直接丢给大模型，模型会编数字、编结论。
> 本项目把"论文里的数值到底对不对"和"回答有没有原文支撑"都变成**可跑、可复现、带页码溯源**的检查，
> 并给出**经过限定说明的量化评测**。
>
> 实测：在一篇 25 页遥感论文的全文（约 9 万字符）上，让 DeepSeek-V3 直接找数值不一致 ——
> 注入 6 处已知缺陷，它**一处都没找出来**。详见 [评测](#评测)。

---

## 这是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 论文**内部**数值自洽性检查 | 通用 PDF 问答（那已是红海） |
| 基于**你自己的**文献库问答 | 在线文献检索 |
| 每条结论**带页码与原文片段** | 文献综述生成 |
| **确定性回查**引用是否真有支撑 | 让 LLM 自由判断「论文写得好不好」 |
| 只读本地 Zotero 库 | 云端服务 |

## 核心能力

### 一、数值自洽审查（`pixi run audit`）

| 编号 | 检查内容 | 状态 |
| --- | --- | --- |
| **C1** | 样本量跨位置一致（同一**来源**的站点数/样本数） | ✅ |
| **C2** | 同一**对象**的指标跨位置一致（R²/RMSE/MAE/Bias…） | ✅ |
| **C3** | 指标间数学关系：`R² ∈ [0,1]`、`RMSE ≥ MAE`、`|Bias| ≤ RMSE` | ✅ |
| **C4** | 百分比与分母可复算 | ⛔ 未实现（规划中） |
| **C5** | 单位量纲一致（同一对象的指标不得换单位） | ✅ |
| **C6** | 时间/空间范围一致 | ⛔ 未实现（规划中） |

### 二、可溯源问答（`pixi run ask`）

漏斗式四步，每一步都是为了让回答**可核验**：

```text
检索（混合）  →  证据不足则拒答  →  生成（强制标注引用）  →  回查核验
                ↑ 不进入生成，        ↑ 只许引用给定片段      ↑ 确定性比对，非再问模型
                  不靠先验硬答
```

| 机制 | 做法 | 效果 |
| --- | --- | --- |
| **混合检索** | 向量（BGE-M3）+ BM25，**RRF 融合**，去重守卫 | 专有名词/缩写（LSE、TRI、GLASS AVHRR）不丢召回 |
| **强制引用** | prompt 限定「只能依据给定片段，每个数值断言必须标 `[来源N]`」 | 有据可查 |
| **回查核验** | 把答案的数值断言拿去**其引用的片段**里做字符串比对 | **编造的数字会被抓出来**（确定性，不调模型） |
| **拒答** | 检索无命中或相关度过低时直接拒答 | 库里没有就不答 |

## 快速开始

环境用 [pixi](https://pixi.sh) 管理，分两个环境：

```bash
pixi install              # 主环境（Zotero / 检索 / 审查 / 问答 / 服务）
pixi install -e parser    # 解析环境（Docling，依赖重故隔离）
```

> **为什么隔离**：Docling 的依赖链（torch / transformers / huggingface-hub）与
> conda 侧被固定的 `typer` 版本冲突，独立解算才通。

### 1. 前置：Zotero 设置

只读你的本地库，需在 Zotero 中开启：

> 设置 → 高级 → 勾选「**允许其它应用程序与 Zotero 通信**」

未开启时本地 API 返回 `403`。**Zotero 未运行时**会自动降级为读取 `zotero.sqlite` 的只读副本。

⚠️ 本地 API 的**读请求无需鉴权** —— **切勿把 `23119` 端口暴露到本机之外**。

### 2. 解析论文

```bash
pixi run -e parser python scripts/parse_pdf.py <论文.pdf> data/index/parsed/<key>.json
```

实测成本：原生 PDF 约 **25–110 s/篇**（视页数与图量）；扫描件需 OCR，可达数百秒。

### 3. 构建索引（问答需要）

```bash
cp .env.example .env      # 填 embedding / LLM 的 API key
pixi run py scripts/build_index.py
pixi run py scripts/build_index.py --check   # 核对索引与当前模型指纹是否一致
```

> ⚠️ **索引与 embedding 模型绑定**（`EmbeddingSpec.fingerprint()`）。
> 换模型必须**全量重建** —— 不同模型的向量不可混存。

### 4. 用起来

```bash
# 数值自洽审查
pixi run audit --key <itemKey> --no-llm      # 纯确定性，不调 LLM
pixi run audit --key <itemKey> --inject      # 注入已知缺陷，演示「能抓到」

# 可溯源问答
pixi run ask "用了多少个 FLUXNET 站点做验证？"
pixi run ask "..." --key C7KQG54K            # 限定单篇

# 服务
pixi run api                                 # http://127.0.0.1:8000/docs
```

端点：`/health`（依赖与索引状态自诊断）· `/papers` · `/papers/{key}/facts` · `/audit` · **`/ask`**

### 5. 测试与评测

```bash
pixi run test                  # 全部自检（8 个文件 / 61 项）
pixi run eval --llm-baseline   # A/B 对照评测
```

## 架构

```text
Zotero 本地库
   │
   ├─ 适配层 ── Layer 1 本地 HTTP API（主，需 Zotero 运行）
   │            Layer 2 zotero.sqlite 只读副本（降级）
   │            ⚠️ 数据目录从 prefs.js 发现，不硬编码
   │
   ├─ 解析层 ── Docling（MIT，本地）→ 页码 provenance + 表格行 + caption
   │            ⚠️ 不依赖在线提取服务；不使用 PyMuPDF（AGPL）
   │
   ├─ 检索层 ── 分块（带页码/类型）→ 向量(BGE-M3) + BM25 → RRF 融合 → 去重
   │            ⚠️ 向量落盘用 .npy 而非 FAISS 文件 IO（见「调试记录」）
   │
   ├─ 抽取层 ── 数值型事实 + 位置归因
   │            ⚠️ 科学论文的数值是**散文式**表达，归一化层不可省
   │
   └─ 两条链（LangGraph 状态图）
        audit: load → extract → check → (summarize?) → render
        ask  : retrieve → (refuse | answer) → verify
```

### 为什么 `summarize` 是条件边

- 没有矛盾时不调 LLM（省 token）
- **没配 LLM 时审查链降级为纯确定性报告，而不是失败** ——
  核心检查项本来就不依赖 LLM，这正是「降幻觉」的设计前提

## 评测

### 数值自洽审查：A/B 对照

真实论文**不该有内部矛盾**，所以「能不能找到问题」无法用真实数据验证 ——
必须**注入已知缺陷**当 ground truth。两组跑**同一任务、同一批数据、同一份答案**：

| 组 | 做法 |
| --- | --- |
| **A 裸 LLM** | 论文全文（75k~90k 字符，带页码标注）塞进 context，让它直接找 |
| **B 本系统** | 确定性规则（C1/C2/C3/C5） |

语料：**12 篇**遥感论文

| | 检出率 | 误报数 | 成本 |
| --- | --- | --- | --- |
| **B 本系统** | **6/6 = 100%** | **0** | 0 token |
| A 裸 LLM（DeepSeek-V3） | 1/6 = 17% | 0 | 17 s · 78,516 tokens |

### ⚠️ 这些限定条件必须跟数字一起读

1. **N=6 太小** —— 不足以支撑「100% vs 17%」这类断言，只能算**试跑**。
2. **注入器必须满足检查器的前提** —— 后果是：**召回率只在一组「检查器本来就能看见的缺陷」上测量**，
   **天然高估**真实场景的召回。
3. **裸 LLM 是单发朴素基线**（全文一次问完）。更强的基线（分块检索、迭代追问、给示例）
   **本实验没有排除**。
4. LLM 组 `temperature=0` 但仍有波动。

**怎么复核**：`pixi run eval --llm-baseline`（结果与注入清单可复现）。

## 一个必须知道的设计难点：数值抽取

第一版按「`指标 = 数值`」写正则，在 4 篇真实论文上命中 **0 处**。

实测到的书写形态**至少 8 种**：

```text
R² ≈0.73                          约等号
R ² of 0.981                      上标被拆成「空格+²」
R 2 reduced from 0.055 to 0.0036  上标被拆成「空格+2」；区间式
an RMSE of 0.0125                 「指标 of 值」
reduced RMSE (23.88 mm/month)     括号 + 单位
bias < 0.001, RMSE < 0.05         不等式
reached ~0.02                     波浪号近似
A VHRR                            单词内被插入空格（反向噪声）
```

**科学论文的数值是散文式表达，不是键值对。** 加入归一化层（上标拆分、破折号、全角、
数字内空格、小数点被渲染成冒号）后，命中从 **0 → 66 条**。

## 调试记录

开发过程中记录的 **23 个问题**（环境依赖 / 外部 API 契约 / 文本抽取 / 误报治理 / 评测方法学）
整理在 **`docs/DEBUG_LOG.md`**，每条含现象、误判、定位手段、根因与教训。

其中最有价值的一课：

> **误报是这个工具的死穴。** 误报数走过 `0 → 8 → 0（4 篇语料）→ 23（扩到 12 篇）→ 1 → 0`。
> **「4 篇上误报为 0」是过拟合到小样本的假象。**
> 而每一条误报的根因，都只能靠**回到原始字节**（`repr()` + 码点）才能定位 ——
> 它们全部来自「想当然」。

## 数据与合规

- **本仓库不含任何论文原文**，也不分发任何第三方文献
- 只读取**用户本机**的 Zotero 库，仅保存 PDF **路径** 与 Zotero **item key**
- `reports/`（审查报告，含论文片段）与 `data/index/`（解析产物与索引）均已 gitignore
- **不使用 PyMuPDF** —— 其 AGPL-3.0 许可会污染本项目的开源许可选择

## 尚未实现 / 已知限制

| 项 | 说明 |
| --- | --- |
| **C4 / C6 检查项** | 百分比可复算、时间/空间范围一致 —— 规划中 |
| **面向科研的文档生成** | 本项目「生成」指**基于检索证据的作答**与审查报告生成；综述初稿、方法对比等**文档生成未实现**，属规划中 |
| **图形内数值** | 散点图上的 R² 标注不在文本层里，取不到 |
| **引用核验是数值级的** | 它抓得住**编造的数字**，但**抓不住误读** —— 例如把「总 96 个站点」读成「30 个站点」，只要 30 出现在所引片段里就会通过 |
| **表格块的跨指标关系判定被禁用** | 表格拼成一行后单元格邻近关系不可靠；单事实检查（如 `R²∈[0,1]`）仍生效 |
| **只支持已解析的文献** | 检索范围 = `data/index/parsed/` 里已有的论文 |
