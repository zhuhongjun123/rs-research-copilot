# rs-research-copilot

遥感科研辅助 Agent —— 直接读你**本地的 Zotero 文献库**，做两件事：

1. **论文数值自洽审查** —— 抓出同一篇论文内部的数值矛盾
2. 可溯源问答与摘要生成

> **它解决什么问题**：把论文 PDF 直接丢给大模型，模型会编数字、编结论。
> 本项目把「论文里的数值到底对不对」变成**可跑、可复现、带页码溯源**的检查，
> 并给出**经过限定说明的量化评测**。
>
> 实测：在一篇 25 页遥感论文的全文（约 9 万字符）上，让 DeepSeek-V3 直接找数值不一致 ——
> 注入 6 处已知缺陷，它**一处都没找出来**。详见 [评测](#评测)。

---

## 这是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 论文**内部**数值自洽性检查 | 通用 PDF 问答（那已是红海） |
| 每条结论**带页码与原文片段** | 文献综述生成 |
| 检查项为**确定性规则**，可复现 | 让 LLM 自由判断「论文写得好不好」 |
| 只读**你自己的** Zotero 库 | 在线文献检索 / 云端服务 |

## 核心能力

### C1–C6 检查项

| 编号 | 检查内容 | 依据 |
| --- | --- | --- |
| **C1** | 样本量跨位置一致（同一**来源**的站点数/样本数） | 确定性 |
| **C2** | 同一**对象**的指标跨位置一致（R²/RMSE/MAE/Bias…） | 确定性 |
| **C3** | 指标间数学关系：`R² ∈ [0,1]`、`RMSE ≥ MAE`、`|Bias| ≤ RMSE` | 确定性（数学恒等） |
| **C4** | 百分比与分母可复算 | 确定性 |
| **C5** | 单位量纲一致（同一对象的指标不得换单位） | 确定性 |
| **C6** | 时间/空间范围一致 | 确定性 |

### 三条防误报护栏

误报是这个工具的死穴。实测中「区间端点被当成两个冲突值」「把邻居括号当成本条对象」
「把图轴刻度当指标值」都曾造成过 **100% 误报**。所以代码里有三条硬纪律：

1. **对象抽不准 → 放弃比较**（宁漏报不误报）
2. **区间端点 / 不等式 → 不参与等值比较**
3. **数学关系只在同一对象的同一句内成立**（跨句比较必出误报；表格块也不参与）

## 快速开始

环境用 [pixi](https://pixi.sh) 管理，分两个环境：

```bash
pixi install              # 主环境（Zotero / 抽取 / 检查 / 服务）
pixi install -e parser    # 解析环境（Docling，依赖重故隔离）
```

> **为什么隔离**：Docling 的依赖链（torch / transformers / huggingface-hub）与
> conda 侧被固定的 `typer` 版本冲突，独立解算才通。

### 1. 前置：Zotero 设置

只读你的本地库，需在 Zotero 中开启：

> 设置 → 高级 → 勾选「**允许其它应用程序与 Zotero 通信**」

未开启时本地 API 返回 `403`。**Zotero 未运行时**会自动降级为读取 `zotero.sqlite` 的只读副本。

⚠️ 本地 API 的**读请求无需鉴权** —— **切勿把 `23119` 端口暴露到本机之外**。

### 2. 解析论文

```bash
# 单篇：PDF → 结构化 JSON（页码 + block 类型 + 表格行）
pixi run -e parser python scripts/parse_pdf.py <论文.pdf> data/index/parsed/<key>.json
```

实测成本：原生 PDF 约 **25–110 s/篇**（视页数与图量）；扫描件需 OCR，可达数百秒。
本机 12 篇语料中 95% 有文本层。

### 3. 审查

```bash
# 真实论文（纯确定性，不调 LLM）
pixi run audit --key <key> --no-llm

# 注入已知缺陷后审查 —— 演示「能抓到」
pixi run audit --key <key> --inject

# 写文件
pixi run audit --key <key> -o report.md
```

### 4. 起服务

```bash
pixi run api     # http://127.0.0.1:8000/docs
```

端点：`/health`（依赖状态自诊断）· `/papers` · `/papers/{key}/facts` · `/audit`

### 5. 跑测试与评测

```bash
pixi run test    # 全部自检（6 个文件 / 42 项）
pixi run eval --llm-baseline   # A/B 对照评测
```

## 架构

```text
Zotero 本地库
   │
   ├─ 适配层  ── Layer 1 本地 HTTP API（主，需 Zotero 运行）
   │            Layer 2 zotero.sqlite 只读副本（降级）
   │            ⚠️ 数据目录从 prefs.js 发现，不硬编码
   │
   ├─ 解析层  ── Docling（MIT，本地）→ 页码 provenance + 表格行 + caption
   │            ⚠️ 不依赖在线提取服务；不使用 PyMuPDF（AGPL）
   │
   ├─ 抽取层  ── 数值型事实 + 位置归因（页码 / block 类型 / 句子）
   │            ⚠️ 科学论文的数值是**散文式**表达，归一化层不可省
   │
   └─ 检查层  ── C1–C6 确定性规则
                └─ LangGraph 编排：load → extract → check → (summarize?) → render
```

### 为什么 `summarize` 是条件边

- 没有矛盾时不调 LLM（省 token）
- **没配 LLM 时整条链路降级为纯确定性报告，而不是失败** ——
  核心检查项本来就不依赖 LLM，这正是「降幻觉」的设计前提

LLM 摘要的 prompt 里有硬约束：**只允许提及已核验的数值与位置，不得引入新数字**。

## 评测

### 方法

真实论文**不该有内部矛盾**，所以「能不能找到问题」无法用真实数据验证 ——
必须**注入已知缺陷**当 ground truth。

两组跑**同一任务、同一批数据、同一份答案**：

| 组 | 做法 |
| --- | --- |
| **A 裸 LLM** | 论文全文（75k~90k 字符，带页码标注）塞进 context，让它直接找 |
| **B 本系统** | 确定性规则 C1–C6 |

### 结果

语料：**12 篇**遥感论文（作者本人的一作/共一作论文）

| | 检出率 | 误报数 | 成本 |
| --- | --- | --- | --- |
| **B 本系统** | **6/6 = 100%** | **0** | 0 token |
| A 裸 LLM（DeepSeek-V3） | 1/6 = 17% | 0 | 17 s · 78,516 tokens |

### ⚠️ 这些限定条件必须跟数字一起读

1. **N=6 太小** —— 不足以支撑「100% vs 17%」这类断言，只能算**试跑**。
   要给出有意义的置信区间，注入样本需到几十处。
2. **注入器必须满足检查器的前提** —— 这是开发中反复踩到的坑（注入的来源名要原样复用、
   C5 注入需同对象配对）。后果是：**召回率只在一组「检查器本来就能看见的缺陷」上测量**，
   **天然高估**真实场景的召回。真实论文里的不一致形态远比注入器丰富。
3. **裸 LLM 是单发朴素基线**（全文一次问完）。更强的基线（分块检索、迭代追问、给示例）
   **本实验没有排除**。
4. LLM 组 `temperature=0` 但仍有波动。

**怎么复核**：`pixi run eval --llm-baseline`（结果与注入清单可复现）。

## 一个必须知道的设计难点：数值抽取

第一版按「`指标 = 数值`」写正则，在 4 篇真实论文上命中 **0 处**。

实测到的书写形态**至少 8 种**：

```text
R² ≈0.73                          约等号
R ² of 0.981                      上标被拆成「空格+²」
R 2 reduced from 0.055 to 0.0036  上标被拆成「空格+2」；区间式
an RMSE of 0.0125                 「指标 of 值」
reduced RMSE (23.88 mm/month)     括号 + 单位
bias < 0.001, RMSE < 0.05         不等式
reached ~0.02                     波浪号近似
A VHRR                            单词内被插入空格（反向噪声）
```

**科学论文的数值是散文式表达，不是键值对。** 加入归一化层（上标拆分、破折号、全角、
数字内空格、小数点被渲染成冒号）后，命中从 **0 → 66 条**。

这也是这个方向至今少有人做的原因：**它不是「写个正则比对一下」**。

## 数据与合规

- **本仓库不含任何论文原文**，也不分发任何第三方文献
- 只读取**用户本机**的 Zotero 库，仅保存 PDF **路径** 与 Zotero **item key**
- 不向任何云服务上传文献内容
- `reports/`（审查报告，含论文片段）与 `data/index/`（解析产物）均已 gitignore
- **不使用 PyMuPDF** —— 其 AGPL-3.0 许可会污染本项目的开源许可选择

---

## 已知限制

- **N=6 的评测只是试跑**（见上）
- 表格块的**跨指标关系判定被禁用** —— 表格拼成一行后指标与对象的对应不可靠；
  单事实检查（如 `R²∈[0,1]`）仍生效
- **C4/C6 仍是简化实现**（C4 只做分母存在性；C6 未覆盖完整时空范围比对）
- 图形内的数值**无法从文本层获得**（散点图上的 R² 标注拿不到）
- 扫描件解析成本高（单篇可达数百秒）
